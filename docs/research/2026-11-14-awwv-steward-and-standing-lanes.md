## 1. How AWWV's integration steward works

### 1.1 Why it exists

- AWWV runs about a dozen sessions at once on one machine. The orchestrator owns sequencing. ORCH:3-4.
- When the steward started (2026-11-13, 21:10 UTC), the roadmap and board were already wrong. They said calibration was 712/711/712/710, but main had moved to 712/711/711/710. Since 2026-11-12, PRs #567 to #590 had merged with nothing registered. The old canon-backlog file had sat since 2026-03-28. T#4 (brief, "Current drift you start with").
- The owner then made it a standing rule: "Make sure that is a standing rule from now on, saves us a lot of pain." ORCH:115.

### 1.2 The standing rule, in full

ORCH:115 says:
- An integration steward lane always exists while any lane runs.
- It is never archived as "done".
- If it ends, crashes or runs out of context, the orchestrator starts a replacement at once from ORCH §5.
- The orchestrator tells it "merged: #N" after every merge, or the steward polls `gh pr list --state merged` itself.
- It stays local, because it edits the coordination files (ORCH:115, ORCH:221).
- Model: "Sonnet or Opus medium (docs work)".
- It also builds process fixes the owner approves, for example ledger fragments.

The WIP limit does not count it: "STEW, R8-dry and one audit don't count" (ORCH:101). ORCH:42 lists it as lane STEW, kind "docs/process", merge rule "Merge on green".

### 1.3 The duty list

After every merge to main, the steward reconciles these (ORCH:117-125):

1. `docs/plans/MASTER_ROADMAP.md`: the current-state line, the §4.1 behaviour-closure register rows, and the sequence line.
2. `docs/plans/COMMAND_BOARD.md`, which is "the derived view; the roadmap wins" (ORCH:119).
3. `docs/open_gates.yml`, checked by `npm run gates`.
4. `docs/plans/plan_index.yml`, regenerated by a tool and never hand-edited.
5. `.claude/current-lane.txt`. This feeds the scope-drift hook, which fires on scenario runs and prints the declared lane (`AWWV/docs/life_lessons/process.md:729-732`, `AWWV/.claude/current-lane.txt:1`).
6. `docs/CANON_PROPAGATION_NEEDED.md`: drain the items that are now true and remove the stale ones.
7. The R8 plan record, for dry-run and qualifying results.
8. The findings register (REG): mark items fixed, with PR links.

The hard limit is ORCH:127: it "never edits `FORAWWV.md` or other panel-gated canon". It lists those items for the orchestrator.

The owner-level docs-in-sync contract the steward polices is ORCH:109-113. Every PR must carry a ledger entry, canon updates for behaviour changes, `CALIBRATION_MASTER.md` and baselines for calibration moves, and a regenerated plan index.

The first-pass brief added items that are really one-off (T#4):
- a branch audit with `git cherry`, listing remote branches with unique commits, no open PR and no `archive/` tag, and deleting nothing;
- a report on whether the PS lane was ready to close, where only the owner closes lanes;
- a canon-backlog triage.

### 1.8 What went wrong

Each item has its evidence.

1. **Auto-merge landed before a review fix.** #599 merged at 23:19 UTC, before the steward's fix commit that kept gate `REPO-CANON-PROPAGATION` open. Main therefore closed the gate with no panel sign-off until #605 landed (T#2042, T#2240; Codex flagged it). The steward then held auto-merge on #605 until Codex had reviewed (T#2145).
2. **The steward's own canon text was wrong.** It wrote the 14-item canon backlog into the Systems Manual. A four-seat panel it was ordered to convene found **12 defects** in round 1. Examples: a cooldown no code reads was described as live, and a "BFS up to 8 hops" really examined one ring (T#2240). The panel finished in three rounds. Lesson: a steward that writes claims about what the code does is writing canon, so it needs a reviewer.
3. **A size-cap test fought the process.** `MASTER_ROADMAP.md` is capped at 60,000 characters by `tests/docs_desktop_v09_truth.test.ts` (REG:281). The steward hit the cap three times in a night: 63,464 characters against the cap (T#591), 430 characters of headroom (T#1082), and 59.3k again (T#3102). Each time it moved old prose verbatim into `MASTER_ROADMAP_ARCHIVE.md`.
4. **The docs-in-sync contract caused the ledger conflicts the steward then had to fix.** Every PR adds its entry at the top of `PROJECT_LEDGER.md`, so parallel PRs conflicted (REG:373, "CG3"). The steward's own #605 conflicted (T#2342). Its fix, per-PR fragment files plus a compile script plus a CI guard plus a `merge=union` stopgap, is a new moving part (PR #613, still open when I checked).
5. **Tooling gaps.**
   - `npm run repo:branches` reports squash-merged branches as stranded (REG:277, "STW1"). The steward matched branches to PRs instead.
   - `tests/sarajevo_constant_inventory.test.ts` rewrites a tracked file on every run, so a stale file dirties trees (REG:422, "STW8").
6. **The machine.** About twelve sessions share an 8-core machine (ORCH:85). The steward's pre-commit hook was slow (T#3722), and a panel seat could not finish a diff because git was too slow (T#1949). The orchestrator can send only about 20 messages each time the owner types, so announcements go in ORCH, not messages (ORCH:167).
7. **Scope growth.** The brief had seven first-pass items. By the end the steward had also convened a panel, tagged 14 branches, diagnosed a flaky test (REG:330, "NF5"), drafted the ledger proposal, and built it. ORCH:115 invites this ("builds process fixes"). **[I]** The role drifts toward the orchestrator's general doer.

- Pushed 14 `archive/*` tags for branches with unique commits, no PR and no tag, so nothing was lost (REG:307 area; T#1471).

- **[I]** After pass 1, most passes were mechanical: update figures, a merged list, register marks, a status row. That part could be partly scripted. The judgment work was the panel, the branch audit and the ledger design.

## 3. What this means for Mandate

Facts about Mandate today:
- The lead merges and commits. Lanes do not commit unless the brief says so (`Mandate:CLAUDE.md:61`; `Mandate:docs/LANES.md:25`, :61).
- "Git history is the ledger" (`Mandate:CLAUDE.md:51`). There is no ledger, no board, no plan index and no gates register.
- Lanes are capped at four, two moving the simulation, and reviewer lanes count toward the four (`Mandate:docs/LANES.md:35`; `Mandate:docs/design/FOUNDATION.md:277`).
- Phase 0 is nine lanes (`Mandate:docs/design/FOUNDATION.md:263-273`).
- LANES defers the steward until "More than four lanes at once" (`Mandate:docs/LANES.md:70`).
- Docs that must stay in sync already show drift. `Mandate:docs/ROADMAP.md:3` and `Mandate:docs/OPEN_QUESTIONS.md:8` say decisions "0014–0026" and "0015–0026", but the decisions index lists accepted records through 0033 (`Mandate:docs/decisions/README.md:33-39`; `Mandate:docs/decisions/0033-forces-scale-and-data-sources.md`). `Mandate:CLAUDE.md:5` also gives the 0015–0026 range.

Two differences from AWWV change what a steward is for:

1. **Half of AWWV's steward duties do not exist in Mandate.** The ledger, the board, the plan index and the gates register are AWWV's derived and bookkeeping files (ORCH:109-125). Mandate has git history, which rule 5 of `Mandate:CLAUDE.md` ("derived data is recomputed, never saved") says is the right source. **[I]** AWWV's steward needed a compile tool and a CI guard just to keep derived docs from conflicting. Mandate should not create them.
2. **Mandate's lead already does integration** (merges, commits, verifies). What AWWV's steward did that the lead should not do is the sweep: docs sync, the zero-loss audit, and a single writer for each shared doc. That is where the lead's context runs out under nine lanes. **[I]**

## Recommendation for Mandate

### The short answer

Run **one** permanent lane from the start of Phase 0: a **steward** that combines integration bookkeeping and docs sync. Do not run separate permanent integration, docs, history or determinism lanes yet. Turn the recurring parts of the steward's job into checks, so its duty list shrinks over time. Split it only on the triggers in "When to split".

Why one, not two: at Mandate's size, a docs steward and an integration steward would each be idle most of the time, and they would edit the same files after the same events. In AWWV the integration steward's duty list was already mostly docs (ORCH:117-125). **[I]**

### Permanent lane 1: the steward

**Purpose.** Keep canon and pointers true after every merge batch and every accepted decision. Make sure no lane's work is lost.

**Model and effort.** Sonnet, medium: the "Docs sync, copy edits, mechanical cleanup" row of `Mandate:docs/LANES.md:44`. It may hand a read-only inventory to a Haiku or Sonnet low subagent (`LANES.md:45`). Go up a row only with a stated reason. Keep it local, because it audits worktrees and branches.

**Triggers** (all can be driven by one line from the lead, or by the steward's own check of `git log`):
- T1. A merge batch landed. The steward records the last synced commit hash in `ROADMAP.md` and diffs `git log <hash>..HEAD`. It needs no merge message. AWWV's message budget was a bottleneck (ORCH:167), and its `gh` polling option (ORCH:115) is the same idea.
- T2. A decision record is accepted, amended or superseded.
- T3. A lane closes. The steward runs the zero-loss audit (below) before the lead archives the lane (`LANES.md:50-55`).
- T4. A phase boundary: the "Phase" paragraph of `CLAUDE.md` and the Next table of `ROADMAP.md`.

**Duties, per trigger.**
- T1/T2: update `docs/ROADMAP.md` (done and next); `docs/decisions/README.md` (index rows and statuses, so each record appears once with the right "superseded by"); the decision ranges quoted in `CLAUDE.md`, `ROADMAP.md`, `OPEN_QUESTIONS.md` and `FOUNDATION.md`; and `docs/LANES.md`'s "Not adopted yet" table, marking when a trigger has fired.
- Findings: be the only writer of `docs/OPEN_QUESTIONS.md`. Lanes report findings to the lead ("Findings outside my scope"). The steward appends them and the lead tags each (act now, park, drop; `LANES.md:35`). This applies rule 5 to docs: one writer per doc.
- T3 zero-loss audit (read-only, report to the lead): `git status` and `git diff --stat` in the lane's worktree; `git cherry` against main for unique commits (not `--no-merged`; `LANES.md:60`); check for junctions before any delete (`LANES.md:62`); list any branch with unique commits and no archive tag. It may create and push `archive/<branch>` tags (as AWWV's steward did, T#1471). It never deletes a branch or worktree.
- After CI exists (Phase 0 lane 0.1): report the status of main's CI run and flag a red or skipped step. Do not fix it.

**May edit** (docs only, one commit per pass, on its own branch in its own worktree; the lead merges):
- `docs/ROADMAP.md`, `docs/OPEN_QUESTIONS.md`, `docs/decisions/README.md`;
- factual pointers in `CLAUDE.md`: the Phase paragraph, "Where things live" and "Commands";
- the tables in `docs/LANES.md` (not its rules).

**May not edit; lists the proposed change for the lead instead:**
- accepted decision records (only a superseding record changes one; `CLAUDE.md` rule 2);
- `docs/VISION.md`, `docs/design/FOUNDATION.md` content, and the hard rules, canon precedence and working-style sections of `CLAUDE.md`;
- anything in `packages/`, `packs/`, `tools/` or tests, except one docs-check script described below;
- any claim about what the code does. AWWV's steward wrote such claims into canon and a panel found 12 defects (1.8, item 2). Code-versus-doc checks belong to the reviewer lane's canon lens (`LANES.md:34`). The steward only checks docs against decisions and against each other.

**Never:** commit to main, enable auto-merge, push outside its own branch and archive tags, touch another lane's worktree (`LANES.md:25`, :61), or start a lane.

**Reports.** At most about 150 words per pass, sent to the lead by `SendMessage`, ending with "Findings outside my scope". No status board and no per-pass row: git log is the record. If the lead wants a single-glance status, put one short "In flight" table inside `ROADMAP.md`, not a new file (`CLAUDE.md:52`).

**Hand-over.** The steward keeps no private state. Its state is the last-synced hash in `ROADMAP.md`, `OPEN_QUESTIONS.md`, and the git history. A replacement starts from this note's section, `LANES.md`, and those three. Replace it after its second context compaction or at the first sign it misreports; AWWV's steward ran out of context once in about 5.5 hours (T#2428, computed). Because nothing lives only in the session, replacing it is cheap.

**WIP.** Exempt it from the four-lane cap in `LANES.md:35`, as AWWV did (ORCH:101). Otherwise one of Phase 0's four slots is always taken (FOUNDATION:277-281). The lead must make this edit.

### How the steward avoids becoming process weight

1. **Every recurring duty becomes a check, then leaves the duty list** (`CLAUDE.md:15`, rule 7). The first checks to build, each in a few lines of the existing `npm run check`:
   - every file in `docs/decisions/` appears in the index, once;
   - every "superseded by N" and "amended by N" names an existing record;
   - the highest accepted decision number quoted in `CLAUDE.md`, `ROADMAP.md`, `OPEN_QUESTIONS.md` and `FOUNDATION.md` matches the index;
   - relative Markdown links resolve.
   The drift in section 3 (decisions up to 0033, docs quoting 0026) is exactly what the second and third checks catch. This script is the one code file the steward may write, in `tools/`, under the lead's review. AWWV had checks like these (the roadmap size cap, the open-gates test) but they sat beside the steward instead of replacing duties.
2. **No derived documents.** No board, no plan index, no ledger, no generated "status" file. AWWV's board is "derived from the roadmap" (ORCH:119), its index regenerated by tool, its ledger compiled from fragments. Each is a second copy that needs its own guard. Generate a view on demand if one is ever needed.
3. **No new process documents** (`CLAUDE.md:52`). Its output is edits to existing docs and its report.
4. **A pass is small.** One commit, docs only, reported in about 150 words. If a pass would touch a file a running lane edits, it waits or asks the lead.
5. **No canon writing.** It lists, the lead decides. This is also the answer to scope creep (1.8, item 7): process fixes beyond docs are a new lane, with a brief, not a steward side job. AWWV's steward built a CI system because its brief let it.
6. **Review its duty list at each phase boundary.** If a duty has not caught anything in a phase, delete it. Count what the steward changed; if most passes are one-line figure updates, script them.

### Roles NOT to make permanent now

- **A separate docs steward.** Combined into the steward until a split trigger fires.
- **A separate integration steward.** The lead already merges. AWWV needed a standing integrator because every PR merged itself (auto-merge) and a dozen lanes ran (ORCH:115, T#4). Mandate merges in series (`LANES.md:33`).
- **A determinism and CI guard lane.** Make it checks, not a lane. Determinism is already tested (`banned-apis.test.ts`; `Mandate:CLAUDE.md:12`), and FOUNDATION §11 builds the state hash on both OSes, saves and honest CI (`FOUNDATION.md:231-239`). The reviewer lane's determinism lens (`LANES.md:34`) covers judgment. AWWV had a determinism auditor as a review seat (`AWWV\.claude\AGENT_TEAM_ROSTER.md:69`), not a standing lane. The steward only reports red CI.
- **A sources and history steward.** Not yet. At present each research lane answers one question with dated, cited notes, and facts come from a lane (`LANES.md:32`, `CLAUDE.md:59`). A standing role earns its keep once history data entry and verification run alongside other work (see the trigger below). Until then the steward adds one thing: it keeps `docs/research/` free of notes the lead has not triaged, by listing untriaged notes in each pass.
- **A retrospective analyst or player council.** AWWV has both on paper and neither ran in the period I could see (section 2). Use a one-off lane at a phase boundary, from the steward's findings list.
- **A Codex-style second vendor and a shared channel file.** Not adopted (it is not in Mandate's setup), and the 343 KB channel file is a warning (section 2).

### When to split

Split the steward into two (an **integration steward** for merges, zero-loss and CI, and a **docs steward** for canon and indexes) when any one of these is true:
- more than four lanes run at once (the existing `LANES.md:70` trigger), or the steward's passes regularly take more than an hour;
- merges move to PRs with auto-merge, as in AWWV (then the PR queue and CI need their own watcher);
- a pass touches files that running lanes also edit, twice in a row.

Add a **sources and history steward** when lane 0.3 (Union 1861 data entry; `FOUNDATION.md:267`) and Phase 1 situations under the sensitive-history gate run at the same time as other history lanes.
