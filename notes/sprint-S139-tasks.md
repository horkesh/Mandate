## Implementation

Operations owns immutable tasks and the default allocation of each approved
axis. Tasks name operation, issuer, executing post, actual blocks, purpose,
regional scope and release condition. A subordinate task/release uses ordinary
support transport, receipt and compliance, including refusal and delay. A
commander's directly held task changes on his local decision boundary.
Conflicting reservations return a typed reason. Completion, command loss,
authority loss and loss of blocks end stale task allocations. Original command
assignments, lot regrouping and locations remain with their existing owners.

Attacks use executing main effort, released available reserves and active
contacting demonstrations. Regional defenders remain exposed. In a mutual
attack, `bsideBlocks` records exposed troops while `bsideAttackBlocks` records
only executing offensive blocks; exposure cannot take command of the attack.
These are combat history, never a second live assignment table. Default
main/defensive tasks preserve approved movement. No name, date or fraction
selects reserves. Schema 7 migrates absent task history without backfilling a
receipt or allocation; the day-40 save was regenerated by its prescribed tool.
